INSTALACIÓN EN RASPBERRY PI
===========================

Este archivo es la bitácora de instalación del satélite de voz. Debemos
actualizarlo cada vez que agreguemos o cambiemos un paso de preparación de la
Raspberry Pi.


1. IMAGEN DEL SISTEMA OPERATIVO
-------------------------------

Hardware objetivo:

- Raspberry Pi 4.
- Tarjeta microSD o almacenamiento USB adecuado.

Imagen utilizada:

- Raspberry Pi OS Lite de 64 bits.
- Arquitectura: arm64 / aarch64.
- Sin entorno de escritorio.

No usar la imagen de 32 bits: el instalador y los artefactos del proyecto sólo
soportan ARM64. Tampoco instalar Raspberry Pi OS con escritorio, porque la UI
se ejecutará directamente en Chromium Kiosk y no necesita un escritorio
completo.

En Raspberry Pi Imager:

1. Seleccionar el dispositivo "Raspberry Pi 4".
2. En "Sistema operativo", elegir:
   Raspberry Pi OS (other) > Raspberry Pi OS Lite (64-bit).
3. Seleccionar la tarjeta microSD o el almacenamiento de destino.
4. Antes de escribir la imagen, abrir la personalización y configurar:
   - Nombre del equipo.
   - Usuario y contraseña.
   - Red Wi-Fi, si no se utilizará Ethernet.
   - Zona horaria y distribución de teclado.
   - Acceso SSH mediante contraseña o, preferentemente, clave pública.
5. Escribir la imagen y arrancar la Raspberry Pi.


2. ORIENTACIÓN DE LA PANTALLA OFICIAL DE 7 PULGADAS
---------------------------------------------------

Estado: procedimiento probado y funcionando.

El case obliga a montar la pantalla al revés de su orientación normal. Hay que
rotar 180 grados tanto la imagen como las coordenadas de la pantalla táctil.

Rotación de la imagen:

1. Editar la línea de arranque:

   sudo nano /boot/firmware/cmdline.txt

2. El contenido de cmdline.txt debe permanecer en una sola línea. Añadir al
   final, separado del parámetro anterior por un espacio:

   video=DSI-1:800x480@60,rotate=180

Rotación de la entrada táctil:

1. Editar la configuración de arranque:

   sudo nano /boot/firmware/config.txt

2. Si existe esta línea:

   display_auto_detect=1

   comentarla de esta manera:

   #display_auto_detect=1

3. Añadir la siguiente línea:

   dtoverlay=vc4-kms-dsi-7inch,invx,invy

   Si ya existe una línea dtoverlay=vc4-kms-dsi-7inch, no duplicarla: añadir
   invx,invy a la línea existente, separados por comas.

4. Reiniciar:

   sudo reboot

Después del reinicio, verificar que la imagen esté invertida y que las
coordenadas táctiles coincidan con la posición tocada.

No utilizar las opciones antiguas display_rotate, display_lcd_rotate o
lcd_rotate. Raspberry Pi OS actual utiliza KMS.

Consideración para Chromium Kiosk:

El parámetro rotate=180 configura la consola, pero una aplicación que acceda
directamente a DRM puede necesitar una transformación adicional. Al probar
Chromium sobre Wayland, verificar primero la imagen y el táctil. Configurar una
transformación adicional de DSI-1 sólo si Chromium continúa invertido, para no
aplicar dos veces la rotación de la entrada táctil.


3. RED WI-FI
-------------

Estado: pendiente de completar debido a los problemas de alimentación.

Después del segundo arranque, NetworkManager mostraba wlan0 disponible, sin
bloqueos y con la radio habilitada, pero no existía un perfil Wi-Fi persistente:

   nmcli -f NAME,UUID,TYPE,DEVICE connection show

Sólo aparecían la conexión Ethernet y loopback. Para crear el perfil persistente
se debe ejecutar:

   sudo nmcli --ask device wifi connect "NOMBRE_EXACTO_DEL_WIFI" ifname wlan0

Si la red está oculta:

   sudo nmcli --ask device wifi connect "NOMBRE_EXACTO_DEL_WIFI" ifname wlan0 hidden yes

Después se debe confirmar y habilitar la reconexión automática:

   nmcli -f NAME,UUID,TYPE,DEVICE connection show
   sudo nmcli connection modify "NOMBRE_DEL_PERFIL" connection.autoconnect yes
   sudo nmcli connection modify "NOMBRE_DEL_PERFIL" connection.autoconnect-priority 10

La prueba de conexión provocó un reinicio por bajo voltaje, por lo que todavía
falta confirmar el perfil y un reinicio conectado únicamente mediante Wi-Fi.


4. ALIMENTACIÓN ELÉCTRICA
-------------------------

Estado: problema confirmado y todavía no resuelto completamente.

Durante las pruebas de Wi-Fi y del entorno gráfico, la Raspberry Pi se apagó o
reinició. La comprobación mostró:

   vcgencmd get_throttled
   throttled=0x50005

Este valor confirmó bajo voltaje activo y throttling, además de registrar que
ambas condiciones habían ocurrido desde el arranque. El cargador debe entregar
5-5,1 V estables y 3 A reales a la Raspberry Pi 4; la calidad y longitud del
cable USB-C también son importantes.

Para monitorizar:

   watch -n 1 'date; vcgencmd get_throttled; vcgencmd measure_temp; uptime'

El valor esperado durante un arranque estable es:

   throttled=0x0

La pantalla oficial puede alimentarse desde los pines 5V/GND de la Raspberry o
mediante una fuente micro-USB separada. Si se alimenta por micro-USB, no conectar
simultáneamente los cables GPIO 5V/GND entre la pantalla y la Raspberry.

El instalador del satélite no bloquea la instalación por bajo voltaje. La
comprobación se conserva únicamente en health-check.sh como diagnóstico.

6. PRIMER RELEASE DEL SATÉLITE
------------------------------

Estado: release generado y validado localmente; instalación real en Raspberry
Pi pendiente.

Versión inicial:

   ha-satellite 0.1.0 para Linux ARM64

Patch actual:

   ha-satellite 0.1.7 para Linux ARM64

El patch 0.1.1 incorpora el layout compacto de 800x480, controles circulares
que no se deforman y símbolos meteorológicos SVG que no dependen de fuentes
emoji instaladas en el sistema.

El patch 0.1.2 identifica el satélite local para que el display sólo muestre
su propio nivel de micrófono, activación, transcripción y conversación. La
selección musical del display incluye también esa identidad, permitiendo que
el servidor mantenga destinos activos diferentes para cada satélite.

El patch 0.1.3 permite desplazar verticalmente con el dedo todas las pantallas
de configuración, con inercia y sin mostrar una barra de desplazamiento. La
pantalla principal continúa fija. También evita seleccionar accidentalmente
los textos de la interfaz, conservando la selección dentro de campos editables.

El patch 0.1.4 corrige el desplazamiento para que la pantalla de configuración
tenga una altura limitada al viewport y agrega arrastre explícito mediante
Pointer Events. El gesto puede comenzar sobre el fondo, textos, tarjetas o
botones; un toque corto activa la opción y un movimiento se interpreta como
desplazamiento. Fue validado en Chrome de macOS antes de empaquetarlo.

El patch 0.1.5 corrige la interacción entre el arrastre y los botones. La
captura del puntero sólo se activa después de superar 10 píxeles de movimiento,
por lo que un toque corto funciona en cualquier punto de una tarjeta y un gesto
deliberado continúa desplazando la pantalla. Fue validado en Chrome de macOS.

El patch 0.1.6 corrige la selección de dispositivos PipeWire cuya descripción
es "null". El satélite ahora prioriza siempre el identificador exacto antes de
intentar recuperar un dispositivo por su nombre guardado y usa el identificador
técnico como etiqueta cuando PipeWire no entrega una descripción válida. Esto
evita que TTS confunda la salida analógica configurada con la salida del
micrófono USB Jieli.

El patch 0.1.7 reemplaza la ejecución aislada de Piper por un worker persistente.
La voz configurada se carga en segundo plano al arrancar el satélite y el mismo
modelo ONNX se reutiliza en las respuestas siguientes. El audio PCM se transmite
directamente a un proceso PipeWire persistente, sin crear WAV temporales. Si se
cambia la voz o la salida desde el display, el satélite reemplaza y precarga el
worker en caliente sin reiniciar el servicio completo.

7. LOCALE, TRADUCCIÓN Y ACTUALIZACIONES AUTOMÁTICAS
---------------------------------------------------

La advertencia SSH:

   -bash: warning: setlocale: LC_CTYPE: cannot change locale (UTF-8)

aparece porque macOS puede enviar LC_CTYPE=UTF-8, pero "UTF-8" por sí solo no
es un locale válido en Raspberry Pi OS. Configurar en raspi-config:

   Localisation Options > Locale > es_CL.UTF-8 UTF-8

y seleccionarlo como locale predeterminado. Comprobarlo con:

   locale
   locale -a | grep -i es_CL

Si el aviso sólo aparece mediante SSH desde el Mac, configurar en ~/.ssh/config
del Mac un locale válido para esa conexión:

   Host raspberry
       HostName DIRECCION_IP
       User USUARIO
       SetEnv LC_CTYPE=es_CL.UTF-8

Para impedir que Chromium ofrezca traducir el display, usar la política
administrada TranslateEnabled. Crear:

   /etc/chromium/policies/managed/kiosk.json

con el contenido:

   {
     "TranslateEnabled": false
   }

El arranque del kiosco debe conservar además:

   --lang=es-CL
   --disable-features=Translate,TranslateUI

La política aplicada puede comprobarse temporalmente en chrome://policy.

Chromium se actualiza mediante APT en Raspberry Pi OS; no posee un actualizador
independiente en esta instalación. Para detener las actualizaciones automáticas:

   sudo systemctl disable --now apt-daily.timer apt-daily-upgrade.timer
   sudo systemctl mask apt-daily.timer apt-daily-upgrade.timer
   sudo systemctl mask apt-daily.service apt-daily-upgrade.service

Dejar /etc/apt/apt.conf.d/20auto-upgrades con:

   APT::Periodic::Enable "0";
   APT::Periodic::Update-Package-Lists "0";
   APT::Periodic::Download-Upgradeable-Packages "0";
   APT::Periodic::AutocleanInterval "0";
   APT::Periodic::Unattended-Upgrade "0";

Si PackageKit está instalado, deshabilitarlo también:

   sudo systemctl disable --now packagekit.service 2>/dev/null || true
   sudo systemctl mask packagekit.service 2>/dev/null || true

Verificación:

   systemctl list-timers --all | grep -E 'apt|packagekit'
   systemctl is-enabled apt-daily.timer apt-daily-upgrade.timer

Los dos temporizadores de APT deben aparecer como masked. Esto no impide usar
manualmente apt update y apt upgrade, pero también detiene la instalación
automática de correcciones de seguridad.
